# HW14 – эмбеддинги, FAISS, оценка retrieval и mini-RAG по базе знаний

## 1. Кратко: что сделано

- **Какая база знаний использовалась и почему:** Учебная база знаний по основам машинного обучения из 5 документов. Тема выбрана из-за семантической связанности понятий (обучение с учителем, без учителя, переобучение, нейронные сети), что позволяет объективно проверить качество retrieval.
- **Как был организован чанкинг документов:** Чанкинг по фиксированному числу символов с `chunk_size=300` и `overlap=50`. Исходно создано 10 чанков.
- **Какая embedding-модель или какой способ векторизации использовался:** `paraphrase-multilingual-MiniLM-L12-v2` из `sentence-transformers`. Эмбеддинги нормализованы, размерность 384.
- **Что показала базовая проверка retrieval:** На 5 контрольных запросах `hit@3=1.0` и `recall@3=1.0`. Все релевантные документы найдены на 1-м месте.
- **Что изменилось после обновления базы знаний:** После добавления 3 документов (градиентный бустинг, функции активации, SVM) retriever стал корректно находить новые документы. Все три запроса показали `changed=True`.
- **Как сработал mini-RAG:** Extractive-подход с первым предложением из топ-1 чанка показал стабильную работу, возвращая осмысленные ответы с указанием источников.

## 7. Анализ

База знаний по ML оказалась удачной для учебного retrieval. Семантическая близость документов создала реалистичные условия. Чанкинг с `chunk_size=300` и `overlap=50` дал сбалансированные фрагменты. Формальная оценка с помощью `hit@k` и `recall@k` позволила объективно подтвердить качество поиска. Эксперимент с `chunk_size` показал, что на малом корпусе параметр слабо влияет на метрики, но меняет количество чанков. Обновление базы знаний наглядно продемонстрировало необходимость переиндексации: без неё retriever не знал о новых документах. Ошибки mini-RAG на общих вопросах показали ограничение extractive-подхода — он не умеет синтезировать информацию из нескольких источников.

## 8. Итоговый вывод

Базовый retrieval-конвейер с `chunk_size=300`, `overlap=50` и моделью `paraphrase-multilingual-MiniLM-L12-v2` показал отличные результаты (`hit@3=1.0`). Главный вывод: качество retrieval необходимо измерять объективными метриками (`hit@k`, `recall@k`). В RAG-системах генератор полностью зависит от retrieval — если контекст не найден, ответ будет неверным.
